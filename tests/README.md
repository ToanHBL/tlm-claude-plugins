# tests/ — one project per ruleset

Each subfolder is a **minimal, real project generated by applying one of the plugin's skills**
(`../skills/`) to the same spec. They exist to prove the rules produce correct, consistent code —
and to surface contradictions in the rules when they don't (see each project's `PROJECT-NOTES.md`
→ *RULES FEEDBACK*).

> One ruleset → one project. Change a rule, regenerate the matching project, confirm it still holds.

## The shared spec

Every project implements the **same feature**: a single **User CRUD screen**.

- List users (loading / empty / error via props, not branch-swaps)
- Create + Edit via a self-managing modal form (React Hook Form + Zod, `register`-first)
- Delete with a confirm (web modal / RN `Alert.alert`)
- Data through `apiClient[Domain]` (TanStack Query on the client; Server Actions on App Router)

Keeping the feature identical is the point: the **only** differences between projects should be the
ones the framework forces. Everything portable lives in `_modules/` and looks the same across all four.

## How each project maps to the rules

Open any `PROJECT-NOTES.md` for: **(a)** the file tree, **(b)** a *file → rule* table citing the exact
`ai/…` and `skills/…` sources each file follows, and **(c)** a *RULES FEEDBACK* section listing real
friction hit during generation (this is how rule contradictions get found and fixed upstream).

## Known drift (read before trusting the web fixtures verbatim)

The two Next.js fixtures were generated **before** two later rule decisions and moved here as-is:

- They still use in-house **`Text`** / **`Toast`** components. The current rules standardize on
  **`TextPrimary`** and **`BaseToast`** (the RN fixtures already use these). Treat the web naming as
  stale, not as the intended convention.
- `nextjs-app-router/` fetches inside `app/users/page.tsx` (older pattern). The current App Router rule
  keeps `page.tsx` thin and fetches in an `async` Server Component Screen (fix #7).

To realign the web fixtures with the current rules, regenerate them or run a targeted sweep
(`Text`→`TextPrimary`, `Toast`→`BaseToast`, move the fetch into the Screen).

## Regenerating

These are fixtures, not apps you run in prod. To rebuild one from scratch: point Claude (with the
plugin installed) at an empty folder and give it the shared spec above, letting the matching skill
drive. `node_modules/`, `.next/`, `out/`, `.expo/`, and native `ios/`/`android/` dirs are gitignored.
